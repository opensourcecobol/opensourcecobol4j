# fix-skipped-test

SKIP_TESTでスキップされているテストを修正して通るようにする。

## 引数

`$ARGUMENTS` にテストの指定を行う。以下の形式が使用可能：

- テストファイルパス（例: `tests/data-rep.src/pointer.at`）
- テスト名（例: `POINTER: display`）
- テストファイルとテスト名の組み合わせ（例: `data-rep.src/pointer.at:POINTER: display`）

引数が指定されない場合は、まずカレントディレクトリの `task.md` を確認する。
`task.md` が存在すればその内容からテスト情報を読み取って自動的に修正を開始する。
`task.md` も存在しない場合は、SKIP_TESTを含むテストの一覧を表示してユーザーに選択させる。

## 実行手順

### 1. テストの特定

テストを以下の優先順位で特定する：
1. 引数が指定されている場合: 引数からテストを特定する
2. 引数がない場合: カレントディレクトリの `task.md` を読み込み、`file` と `test-title` フィールドからテストを特定する
3. `task.md` もない場合: `grep -r "SKIP_TEST" tests/**/*.at` でスキップテストの一覧を表示し、ユーザーに選択させる

### 2. テストケースの解析

対象のテストファイルを読み込み、以下を理解する：
- `AT_SETUP([テスト名])` から `AT_CLEANUP` までがテストケースの範囲
- `AT_DATA([ファイル名], [...])` でテスト用のCOBOLソースコードを定義している
- `AT_CHECK([コマンド], [期待終了コード], [期待stdout], [期待stderr])` でテストを実行している
- `${COBJ}` は cobjコマンド（トランスパイラ）を指す
- `${COBJRUN}` はコンパイルしたCOBOLプログラムを実行するコマンドを指す

### 3. 問題の調査

テストが失敗する原因を調査する：
- SKIP_TESTの行を一時的にコメントアウトしてテストを実行し、エラーを確認する
- エラーメッセージを解析して、何が原因で失敗しているかを特定する
- 関連するソースコード（cobj/, libcobj/）を調査する

### 4. 修正の実施

問題を修正する：
- トランスパイラ（cobj/）の問題なら、関連する.c/.y/.lファイルを修正する
- ランタイム（libcobj/）の問題なら、関連するJavaファイルを修正する

### 5. テストの実行

修正後にテストを実行して確認する：
- ビルドを実行: `./configure --prefix=$(pwd)/local && make && make install`
- テストを実行して確認する

### 6. SKIP_TESTの削除

テストが通るようになったら、`AT_CHECK([${SKIP_TEST}])` の行を削除する。

### 7. 完了

修正が完了したら、以下を行う：
- `./format` を実行してコードを整形する
- コードレビューを実施する（Task toolでcode-reviewerを呼び出す）
- ドキュメントの更新を確認する（Task toolでdocs-sync-inspectorを呼び出す）

## テストの実行方法

tests/ディレクトリで以下のように実行する：

```bash
# 例: miscテストを実行する場合
cd tests
make misc
./misc
```

テスト失敗時のログは `tests/{テスト名}.dir/` に保存される。

## 注意事項

- 一度に1つのテストケースに集中する
- 複雑な修正が必要な場合は、まず調査結果をユーザーに報告して方針を確認する
- テストが通らない場合でも、進捗をコミットして記録することを検討する
