name: ci-loop
description: コードの編集とCIによる確認のループ
---

依頼に応じてコードを編集したら、以下の手順を踏むようにして

1. CLAUDE.mdやユーザからの指示があった通りにローカルでのテストや検証、レビュー、リンター等を実行する
2. コミットする。この時のメッセージにClaudeが書いたというような文言は入れない
3. git pushする
4. CIがトリガーされるのでそれを監視する。そのなかのジョブが1つでも失敗したら、すぐに調査と修正に着手する。他のジョブの終了は待たない。CIが成功したら作業は終了とする
5. CIの失敗に伴う調査と修正が終わったら1に戻る

また、例外としてGitHub側のインフラのエラーや一時的なネットワークエラーによるCI失敗は、失敗したジョブ(その失敗したジョブにより実行されなかったジョブ)のみを再実行して、それで成功すればOKとしてよい。

これに加えて、Pull RequestのCIはPushのCIより重いことに考慮して。
例えばすでに作成したPRのソースブランチをを編集する必要がある際、CIの失敗する可能性が低い編集の場合はソースブランチを直接編集し、そうでない場合は一度別のブランチを作ってそこで作業してひと段落したらソースブランチにマージするといった、作業の高速化を意識して
